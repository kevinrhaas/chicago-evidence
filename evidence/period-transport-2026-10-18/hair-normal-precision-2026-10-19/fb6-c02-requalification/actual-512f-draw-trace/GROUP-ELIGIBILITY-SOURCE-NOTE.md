# Conditional multimaterial ghost optimization — source only

Current source answers YES to the structural question: buildPlan uses the whole geometry confidence range for an ordinary multimaterial mesh. renderGhost then maps every material-array entry through twinOf, so a material group containing no ghost grade can still submit a draw and discard every fragment. This is not yet evidence that the failed331-call frame contains such a group. Current successful boot diagnostic has no sample rows at this review snapshot.

Smallest candidate if actual trace proves such a draw: for the ghost pass ONLY, replace a material-array slot with null when every effective group using that index is proven unable to produce a ghost fragment and the material is actually ghostable/patched. Pinned Three projectObject skips null group materials (three.module.js17911–17915). Preserve indices and original materials in finally. Never flip shared material.visible; never suppress a group whose slot is shared with another eligible/unknown group. Single-material meshes ignore geometry groups in Three, so this technique must be restricted to material arrays. Batched/instanced geometry needs its current separate eligibility contract; exclude it from the first optimization unless actual instance ranges are proven.

Proof of group range must use actual referenced vertices: indexed geometry through index entries, nonindexed through vertex positions; intersect group start/count with drawRange and actual available index/vertex count. Cache must include confidence-attribute identity/version, index identity/version, group start/count/materialIndex layout, and drawRange, not just the confidence version. Missing arrays, invalid/nonfinite values or unresolved ranges keep the original conservative behavior. upload-release currently preserves ONLY whole geometry confidenceRange; either populate correct group proofs before CPU release with provenance/version tokens, or retain unknown fallback after release. Do not rescan an empty array and conclude no content. Geometry shared across objects requires material-slot checks per object.

Use the shader's actual step-band boundary semantics for a proof. In particular reconstructed includes confidence exactly0.75; do not reject it using max<=0.75. A safe reconstructed-only exclusion is a finite maximum STRICTLY below0.75. For inferred, include values exactly0.25 and exclude values>=0.75. A min/max interval is conservative across interpolated triangles; it cannot justify dropping a mixed-grade triangle merely because its endpoints do not equal a named grade.

Only skip a patched material that would receive its actual CHICAGO_GHOST_PASS twin and whose fragment shader is proved to discard these nonghost values. Unpatched or dither materials can take a different shader path; do not call their duplicate submission a guaranteed no-op without separate evidence. Temporary null slots do not change opaque or shadow passes and must be restored even if renderer throws.

Required evidence before implementation: actual object/material/group/pass rows, matching confidence/index/drawRange/material flags and supported range, summed draw deltas matching renderer.info. If a DoubleSide ghost twin submits two draws, both may be necessary for eligible surfaces; nulling a proven fully-discarded group can save both while preserving its zero visible contribution. Do not forceSinglePass on real volumetric content or weaken330. No application/harness changes or browser/test execution by this reviewer.
