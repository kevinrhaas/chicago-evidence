# Proposed inspection hardening; not applied

Patch: `/workspace/shared/human-inspection-hardening.patch`, rooted at the chicago repository root. Only `chicago/4d/tools/human_teamster.html` and `.mjs` change. Original application files remain untouched. Syntax checks and `git apply --check` pass; no default browser proof or Blender run was repeated.

- Require an actual decoded base-color map on every runtime `skin`/`skin__variant` material. Report JSON material path, declared texture index, runtime GLTFLoader texture association, image index/name/MIME/embedded buffer view, and actual decoded width/height. A flat-color-only model can no longer pass merely because `every([])` returns true. Unique runtime materials are inspected separately even if they have the same name.
- For each actual lod0 screenshot, return projected bounds from the loaded, deformed, rendered-index vertices. Whole-body views measure all visible human meshes. Close views measure >=50%-head/jaw/eye-weighted skin/eye/hair/headwear/mouth vertices; this is explicitly a head-geometry target, not proof of correct facial landmarks or anatomy.
- Require finite camera-front projections inside a 2% viewport margin, zero sampled vertices under the header, and >=20% viewport-height coverage for close detail. Save framing receipts beside screenshot filenames; failed framing becomes an explicit harness failure. Existing camera selection remains unchanged, so cropping is exposed rather than silently reframed.
- Label the existing grounding evidence precisely: idle phase zero, minimum actual footwear vertex Y split by world-X sign, +/-20mm tolerance. It does not claim a walk stance, limb identity, continuous collision proof or lack of skating. No invented walk-contact definition is added.

Remaining limits: decoded map binding and image dimensions do not prove correct UV anatomy, useful color variation, pixel sampling on every surface or photographic quality. Head-weight selection can reveal a weighting defect but is not an anatomical landmark annotation. Vertex/header checks do not prove every rasterized triangle avoids overlay occlusion. Initial CI artifacts should be inspected before applying this patch alongside the eye follow-up.
