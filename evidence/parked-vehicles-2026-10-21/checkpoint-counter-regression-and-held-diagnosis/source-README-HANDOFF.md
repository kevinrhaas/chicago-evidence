## Existing contract and defect

`gpu-pick.js:420–447` deliberately saves `renderer.info.render`, turns autoReset off for private1pixel passes and restores every saved render field afterward. Its own comment says these passes are not the visitor frame. `driver-draws.js` adds multiDrawExtra to info.render.calls so the frame's real batched submissions are counted. It resets with info.reset but had no counterpart to the GPU pick's manual info.render restoration. Thus native multi-draw pick entries past the first survived when their corresponding ordinary calls/triangles did not. A stats read before the next info reset could combine visitor frame calls with leftover private pick extras. Without the extension, per-entry info calls were already restored and no extra tally leaked. This is a counter-contract bug, not evidence yet that this CI frame's423/669 excess is its effect.

The correction does NOT reduce physical GPU work. It keeps the existing visitor-frame accounting boundary consistent across both halves of the driver counter. Ordinary frame colour, shadow and Ghost passes remain counted together exactly as before; neither budget nor units becomes rendererCalls. Existing moving-frame timing/performance still includes real picker work. Optional diagnostics expose private work separately; that work is not silently pretended to disappear.

## Minimal proposed correction

Only2application source files change in `UNMEASURED-driver-pick-counter-preservation-against-2aebef95.patch`.

- `driver-draws.js` exposes `preserve()`, returning an idempotent closure that restores only its extra tally. The caller also restores info.render, as documented. Nested scopes restore in reverse order. The native-acquired flag and wrapped extension stay live, including first lazy acquisition inside a private pick. No extension is asked for earlier, no draw wrapper/math/reset changes, no counter/budget bypass.
- `gpu-pick.js` saves that restore closure beside the original render snapshot, and invokes it in finally with info restoration. This applies to synchronous and asynchronous APIs because both draw through drawPick before any deferred read awaits. An inner cleanup finally also restores frame flags/camera/pool when target or clear restoration throws; the extension tally restoration runs even if assigning info.render throws. No geometry, shader, material policy, candidate set, picking answer or gaze cadence changes.
- Before restoration, it reads private rendererCalls and multiDrawExtra delta. After all normal target/colour/flags/info/driver/camera/pool restoration it emits an existing optional logger event `pick-work`, with rendererCalls, multiDrawExtra, draws. Without a tracker, driver fields are **null**, never a renderer-call substitute. Native false with a tracker correctly has zero extra and per-entry draws. The main already connects this optional logger to the black box; the logger accepts arbitrary event kinds/fields, so no new public UI or black-box code is required. Its compact human summary currently shows the event name only; the structured entry preserves numeric data.

A diagnostic callback throwing on the new post-work event cannot interrupt restoration because it runs afterward. Existing pre-work `pick` callback behavior is unchanged. A setRenderTarget/clear restoration error still propagates; counters/flags/camera/pool are restored where possible, but the failed target/colour operation is not falsely claimed to succeed. No error suppression is added.
