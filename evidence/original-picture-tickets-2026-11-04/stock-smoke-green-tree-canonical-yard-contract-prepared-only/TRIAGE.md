# Read-only stock-smoke triage: Green Tree yard and mobile shadow reach

No application source, Git refs, tickets, publication or GPU was changed by this triage.

## Yard: an established changed-domain contract, not a reason to restore duplicate geometry

The actual source generator generate_yard_goods.py _green_tree_wagon_shed deliberately returns no shed or covered wagon when the actual canonical sidecar enclosed_left_annex.value.shoulder_enclosed is exactly true. Current town_trade_goods.json contains exactly this refusal and no sheds. Andreas's closed shoulder and Trowbridge's open bay are competing retrospective readings; placing both duplicates the occupied ground. Smoke stage2 predates that choice: it insists on one shed and positive vertices for the absent covered wagon, plus a misassignment control that requires an existing shed.

UNAPPLIED-GREEN-TREE-CANONICAL-YARD-CONTRACT.patch is a proposed repair of those expectations. The closed branch is selected only by exact true. It requires positive native GLB foot-edge samples on two exposed shoulder wall edges, outside the connector's own footprint and away from shared corners; it also requires no shed, no under_shed wagon, no owned covered-wagon points, no shed vertices, and exactly the explicit generator refusal. All original open-bay geometry/4.6m/clearance/tilt/owner-displacement checks remain in the alternate branch. Generic ownership controls still test missing, unknown, misassigned, outside-buffer, overlap and bench displacement; the closed branch additionally rejects synthetic phantom shed and covered-wagon owner tags. There is no 0-or-1 count allowance, threshold decrease or source datum change.

The native foot expectations are a proposed check, not an observed browser pass. The GLB contract is u -> +X, v -> -Z; buildings.feetOf reports actual ground-edge samples in local metres. Required 0.05m coordinate allowance matches building-feet.js's native ground-plane tolerance; counters require at least two points per exposed edge. The canonical shoulder polygon is 7.62..11.22 by5.59..12.39, with the connector beginning atv7.89; outer-wall samples are restricted to the exposed5.84..7.64 segment so the connector alone cannot satisfy the check. Root must review and actual published stage2 must run before accepting it.

The existing pure owner test test_occupied_annex_components_preserve_the_open_bay already builds open and closed interpretations in the real accumulator, proving respectively no solid walls in the bay and a closed occupied shoulder. The proposed owner-extension patch adds a direct call to the real yard generator for both choices: closed=>exactly one refusal/no shed/no coveredwagon; open=>one shed + one wagon correctly bound under it/no refusal. Two focused tests executed against the actual source-bound fixture and proposed extension: PASS2, 0.166s, no Blender/export/cache writes. Proposed smoke syntax check PASS; no GPU/current full smoke/source-gate PASS claimed.

## Shadow: retain the real red; proposed bias change is NOT recommended

Actual desktop shadow-delta passed with worst5; mobile failed with worst3 against the unchanged4, mean0.02, both restored0. The current mobile rig correctly states120m/1024map/0.234375m texel. The original threshold was calibrated on an earlier town, and source reading does not prove why this town now yields3.

A diagnostic UNAPPLIED-SHADOW-REACH-BIAS-LIFECYCLE.patch was prepared after noticing that setShadowReach updates texelM but, unlike setShadowRig, does not recompute shadow biases. Its pure owner replay passes and rejects stale reach biases. HOWEVER, setShadowReach is explicitly a harness-only counterfactual that isolates reach at a fixed map. Recomputing bias changes a second cause in the frame and could make a broken reach appear live solely through the bias delta. Parent caught that confound. The T3054 contract derives biases when maps are sized; the held-reach probe keeps that map unchanged. Static omission is insufficient to call it a product bug. Mark this patch DIAGNOSTIC ONLY / NOT APPROVED; DO NOT APPLY to manufacture worst>=4. No threshold, camera or assertion change is justified. Actual stage9 should remain honestly red until its cause is established or an independent physical-shadow measurement proves a valid instrument correction.
