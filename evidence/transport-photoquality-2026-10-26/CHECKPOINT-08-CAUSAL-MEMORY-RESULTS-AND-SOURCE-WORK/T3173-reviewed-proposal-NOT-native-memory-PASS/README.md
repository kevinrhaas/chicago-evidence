# External proposal: apply the existing light texture policy to embedded GLBs and release uploaded compressed source levels on desktop

This packet changes no application checkout. Its baseline is carriage HEAD5b658e7e3267be14d81296a89a1eef9459c21afc. The 5-file patch is a proposal; no native browser, memory, visual or whole-app acceptance is claimed.

The light-profile mip-0 drop in ktx2.js currently runs only through loadCompressed() for library sheets. registerKTX2() hands the unwrapped loader to GLTFLoader, so embedded KHR_texture_basisu images bypass that existing tier policy. The proposal wraps GLB image delivery on every profile to isolate level descriptors from the transcoder cache. Light additionally clones the source and keeps the original chain from mip1. The raw transcoder cache stays full. A WeakMap keeps a stable reduced source per cached full texture so repeated deliveries share the GPU source. Each delivered chain owns its level descriptors, so releasing its level.data cannot mutate another delivery, the reduced cached variant or the full cache. The encoded recovery record retains this adapter, so a residency refill has exactly the same dimensions as the initial light decode. Full-profile GLB loading uses the same ownership adapter while retaining every original mip byte, dimension and GPU source identity. Single-mip inputs retain their only mip.

Separately, desktop source mip arrays remain in the page after their GPU upload because texture-residency.js's releaseLevels holding set is enabled only by closeImages, supplied as coarse from main.js. The proposal adds a separate releaseCompressedLevels setting, enabled for the application at every texture-residency profile. Desktop keeps encoded bytes for recovery, prepares its original 64-texel stand-ins before releasing the arrays, and uses the existing refill and GPU upload path when an evicted texture comes back. It changes no desktop image, mip, shader, source GLB, geometry, detail budget or GPU allocation. Desktop ImageBitmap closing remains disabled. The original option default preserves callers outside main.js.

44 focused controls passed against actual Three Source/CompressedTexture/Group/Mesh objects with deterministic loader and GPU-property doubles. They cover cache/source isolation, exact tail bytes, repeated decode, error propagation, single-mip validity, full-profile identity, uploaded-only release, no-encoded guard, valid populated stand-ins, exact original full-chain refill/upload, repeat release and zero roundtrip problems. This is not actual decoding or WebGL validation.

The actual historical e97 light reading's 77,596,304 resident GLB bytes come from sourceBytes() summing real compressed mip payload byte lengths once per source/sampler. The native GL meter independently counts compressedTexImage2D data lengths or block-aligned texStorage2D allocations; the layer texture estimate of 479 MB is not that measurement and is not used for this projection. Removing the top level from ordinary complete square mip chains would save about three quarters of those resident GLB GPU bytes, around 55.5 MiB; block floors and actual chains require native measurement. No 391.3 MiB result is claimed. Historical T2828 documented 18,636,391 encoded recovery bytes for the same 77,596,304 compressed source bytes. Desktop's source-array release could save roughly 56 MiB net if its current source set matches; that is a projection, not a desktop reading.
