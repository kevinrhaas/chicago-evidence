# V4: reread released source textures through the existing candidate lifecycle

This is an external incremental patch over frozen V3. It retains application keepAssetBytes:false, the public loader default/API and the complete V2 texture policy. No cache or manager framework is added. Only main.js, texture-residency.js and the existing StructureVersions test owner change. The runtime module binding remains4.

The actual two-controller negative control reproduces the prior bug: after the first manager releases compressed source mip payloads, rebuilding directly from those source textures creates zero-byte stand-in tails. The source helper therefore reads actual compressed mip payload lengths, including raw/cloned textures without any userData release marker. Main's existing rereadReleased predicate now selects geometry-released OR texture-released rows, while still skipping the freshly loaded Glessner row. Existing loadDetailAsset, Promise.allSettled, candidate registry, reread/retired/discard arrays and atomic transaction handling remain the implementation path.

A narrow same-source texture-presence check compares required stable node/material ordinal plus material-name/slot-key multiplicities before applying any reread rows. It uses no UUID, GPU identity or format equality, and accepts compressed→RGBA fallback when the required texture remains. This catches the actual pinned GLTFLoader behavior where an encoded-image decoder error is logged but its texture becomes null and the overall parse fulfills. That actual diagnostic is retained. If a required texture is missing, the existing transaction discards successful candidate reads and keeps the old world.

The actual existing StructureVersions owner passes47controls: all32 prior controls plus15 new controls. It executes actual production reread/discard definitions and real pinned GLTF geometry/material/sampler parsing; only image transcoding/GPU properties are deterministic doubles. The first production residency release and shared-image cache retirement are real. Refetch/reparse produces a populated second manager and successful encoded return. Markerless raw/clone, regular/live/no-mip cases are checked. Old phone geometry release and fresh Glessner skip are preserved. Actual encoded-image, corrupt-GLB and HTTP404 failures all preserve old visible/registry state and dispose successful partial candidates; HTTP failure exercises the existing2asks. No production error or vendor behavior is suppressed.

No app checkout or browser was changed by this preparation. Actual desktop detail-switch load cost, uploaded-resource behavior, unchanged Full images, native memory and root acceptance remain unrun for V4. The prepared observer must run against the exact new runtime4 manifest under root's separate renderer grant.

Independent review found a compensation hole in the initial aggregate name/slot multiset: another same-name node could gain a map while the required original node lost it. The final helper keys each required slot by stable scene traversal ordinal and material-array index as well as material name/slot. Two real negative controls reject compensation across nodes and material-array indices. The older patch11030b1e and its45-control transcript remain historical, not the selected revision.
