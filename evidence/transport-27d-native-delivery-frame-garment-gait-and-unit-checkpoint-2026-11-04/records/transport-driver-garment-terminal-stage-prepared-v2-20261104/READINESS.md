# Prepared terminal stage V2: real hashes, installation disabled

This preparation is outside APP. No generator, model decoder, test, browser or GPU
has run here, and no application file or Git ref was edited. V1 is preserved
unchanged as the rejected raw-copy route. V2's recipe records all four actual
prototype output digests and four actual positive admission receipt digests, but
`installed` remains **false**. ROOT must review and test the portable reproducer
before applying this source parcel or installing the assets.

The MASTER outputs are the prior exact LOD0-cloth retention prototypes. The WEB
outputs are the new, separately qualified **single-skin weighted rebind V3**
prototypes. WEB0/WEB3 inverse bind matrices differ; copying their raw POSITION and
NORMAL into skin0 was rejected and is not requalified here. V2 derives new FLOAT32
POSITION/NORMAL, and an existing TANGENT when present, using the admitted native
rest-weighted destination-inverse × source basis. JOINTS/WEIGHTS/UV/index component
bytes remain source-exact. The original destination one skin, nodes, IBMs, rig,
body, clips, material/image declarations and complete BIN prefix remain exact.
The fixed world-position residual stays 1e-6m at rest/0/2.75; normal residuals are
reported without inventing an angular acceptance bar.

The production module copies the admitted V3 append/encode block and rebind math
function bodies unchanged. It uses explicit JS JSON.stringify GLB encoding for WEB
and the frozen Python compact-JSON encoder for MASTER. Their serializers are not
assumed interchangeable. Each output must reproduce its actual bound digest:

The portable generator has no canvas, image codec or machine-specific package
dependency. It resolves THREE, GLTFLoader, Meshopt and their helpers relative to the
application's committed vendor tree and pins those exact files. A named
`loadMaterial` plugin suppresses texture loading while preserving raw input
GLB/parser JSON and the native geometry/skin path, including
`SkinnedMesh.normalizeSkinWeights()`. Material names remain available for garment
selection. No images are decoded and no image validation is claimed by this
generator. Protected JSON plus the full old BIN prove encoded image preservation;
the independently recorded full native/image and 32-PNG render receipts provide
the separate image review. ROOT's later exact-byte regeneration must confirm that
the texture-skip runtime reproduces the real candidate; drift fails closed.

The historical chain remains canonical export → natural standing → seated looking
→ terminal garments. Standalone reproduction rebuilds standing and seated parent
and donor bytes through the original generators and checks their exact immutable
`edfc3ed` payload hashes. It never accepts an installed asset or saved prototype
receipt as a regenerated answer. The standing generator is unchanged. The seated
generator patch adds only two terminal call sites; its original pose, curve,
parent, timing and derivation functions are unchanged.

Exactly four LOD3 terminals change. Four explicitly enumerated LOD0 files are
hash-checked no-ops. The real-chain test retains corruption, duplicate/unlisted
parent, wrong-donor, wrong-output and double-apply rejection, and adds rejection of
the old raw-copy route. Original tests are untouched. All tests remain unrun here.
